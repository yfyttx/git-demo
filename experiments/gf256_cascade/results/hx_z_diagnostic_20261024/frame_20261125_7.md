# (H_X^{\rm cas}) Z-side decoder diagnostic

Fixed matrix seed `20261018`, channel seed `20261125`, `p_D=0.07125`, zero-based
frame `7`. The X estimate was exact and passed its syndrome. `H_X^cas` has 970
GF(256) check rows. Counts below are unsatisfied rows after decoding. The full
matrix OSD-1 candidate passed the syndrome check but still failed logical
equivalence, as described below.

| Z candidate | Prior | Iterations | Unsatisfied `H_X^cas` checks |
| --- | --- | ---: | ---: |
| Current `conditioned_robust` result | decoded X, which was exact | current schedule plus robust path | 5/970 |
| Full-matrix GF(256) BP | marginal bit prior `2p_D/3` | up to 50 | 838/970 |
| Turbo BP | oracle true X | 10 rounds × 10 outer iterations | 5/970 |
| Full-matrix GF(256) BP | conditional prior from decoded X, which was exact | 200 | 125/970 |
| Syndrome-guided beam repair | conditional prior from decoded X, which was exact | width 128, depth 12 | 5/970 |
| Localized order-1 OSD | posterior from 200-iteration conditional BP | 64 weakest free symbols, 4 improving passes | 18/970 |
| Full-matrix order-1 OSD | posterior from 200-iteration conditional BP | 256 weakest free symbols; 65,281 candidates | 0/970 |

Additional Turbo schedules using the decoded X prior (3, 5, 10, and 20 rounds,
10 outer iterations per round, damping 0.3) also failed the syndrome on this
frame. This is a single-frame diagnostic, not a FER estimate. Since X was exact
and the oracle-X Turbo still missed five checks, the failure on this frame is
not explained by an incorrect X estimate alone. More iterations improved the
full-matrix conditioned BP relative to its 50-iteration behavior, but it still
did not converge to a valid syndrome.

A bounded postprocessing search was also tried from the current Turbo candidate.
It used only the full `H_X^cas` syndrome and decoded-X conditional channel priors,
and expanded symbol changes that exactly repair one currently unsatisfied row.
With beam width 128 and depth 12 it did not improve the candidate: it remained
at 5 unsatisfied checks. This suggests that simple low-depth syndrome repair is
not enough; it does not prove that no valid/low-cost correction exists.

A localized order-1 OSD pass was then applied to the 200-iteration full-matrix
BP candidate. It builds a GF(256) system on the currently unsatisfied check rows,
chooses a reliability-ordered pivot set from their neighboring symbols, and
tests single-symbol deviations on up to 64 least-reliable free symbols. Four
successive passes reduced the unsatisfied-check count from 125 to 18, but did
not produce a valid full syndrome. This is a useful diagnostic reduction, not a
successful decode: the candidate still fails the syndrome and therefore cannot
be counted as a corrected frame. The implementation is diagnostic-only and
does not change the normal FER decoder.

The full-matrix OSD-1 prototype then selected a reliability-ordered independent
set of 970 pivot symbols from all 3,492 variables, fixed the remaining symbols
to their BP hard decisions, and tested every nonzero replacement for the 256
least-reliable free symbols. The pivot solve guarantees a candidate for the full
system; a fresh full-syndrome check confirmed 0/970 unsatisfied rows. However,
the highest-posterior candidate in this order-1 list was **not** stabilizer
equivalent to the true error (post-hoc simulation evaluation), so it remains a
logical failure. It differed from the true Z error in 629 GF(256) symbols.
Thus full-matrix OSD repairs the syndrome on this frame, but this limited OSD-1
list has not solved its quantum logical-decoding problem. Truth was used only
for the final logical-equivalence evaluation, never to select the candidate.

The actual error is known to the simulator for evaluation only; it is not used
in any of these candidate decoders. Reproduce with:

```bash
/tmp/gf256_cascade_build/gf256_cascade_simulate 8 20261125 0.07125 conditioned_robust 7
```
