# 同输入 BP 核对与 G2 信道变换对照

核对日期：2026-11-18。运行结果保存在 `results/bp_implementation_audit_20261117/`。

## 实验设置

固定外层矩阵种子 20261019，GF(256)、P=97、194×582；主对照采用当前级联 Z 侧使用的 Delta 多项式基矩阵。物理位边缘翻转率 f_m=0.0475（退极化参数 p_D=0.07125），噪声种子 20261121，BP 最多100轮。内码 H2 为1×9全一行，G2=[I8|1] 为8×9。

主对照只运行 Z 外层分量，不使用 X 条件信息或后处理。这里统计的是外层错误符号向量未精确恢复的块错误率，不是完整量子逻辑 FER。此前直接 Kasai 1000帧实验为50轮；本次各组统一100轮，不将两次计数当作同帧对照。

## 一、同输入核对

C++ 与 Python 分别读取同一外层矩阵、综合征、256项符号先验和迭代上限：

| 配置 | 比较例数 | 硬输出不一致 | 停止轮数不一致 | 综合征状态不一致 |
|---|---:|---:|---:|---:|
| Delta 多项式基，原始先验 |20|0|0|0|
| Delta 多项式基，G2 精确先验 |20|0|0|0|
| Delta 多项式基，故意使用原始先验 |20|0|0|0|
| Gamma 多项式基，原始先验 |20|0|0|0|
| Delta 对偶基，原始先验 |20|0|0|0|
| 合计 |100|0|0|0|

比较的是最终硬输出、停止轮数和综合征状态，并未宣称逐条浮点消息完全相同。此结果没有发现两份实现的输出差异，不能证明所有输入上均无实现错误。旧接口与显式先验接口也做了输出核对，但二者共用 C++ 内核，不算独立实现验证。

## 二、固定 C++ BP，只改变待译错误及对应先验

每帧生成582个9位独立伯努利错误块。原始组取每块前8位；G2组取前8位分别异或第9位。两组共享底层噪声抽样，但错误向量与目标综合征随变换改变。两份语言实现的核对才是严格的相同输入比较。

| 输入 | 先验 | 外层块错误 | 综合征失败 |
|---|---|---:|---:|
| 原始8位错误 | 原始精确先验 |5/100（5%）|5/100|
| G2变换后错误 | 变换后的精确先验 |80/100（80%）|80/100|
| G2变换后错误 | 故意沿用原始先验，失配对照 |100/100（100%）|100/100|

原始组与精确投影组：共同失败5帧，原始成功而投影失败75帧，反向0帧，共同成功20帧。失配先验组是诊断用负对照，不是推荐译码方式。

## 为什么信道变换会影响同一个 BP

令 f=f_m，w(a) 为多项式基8位表示的重量，原始符号分布为

\[
P_E(a)=f^{w(a)}(1-f)^{8-w(a)}.
\]

由于 G2=[I8|1]，第9位错误会同时翻转输出的8个位。因此

\[
P_U(a)=(1-f)P_E(a)+fP_E(a\oplus255).
\]

这是本实验使用的精确联合符号先验，已包含符号内部8个位的相关性，不能替换成8个独立伯努利变量。每一输出位的边缘翻转率为

\[
P(U_i=1)=2f(1-f)=0.0904875.
\]

边缘率升高本身不是性能差的完整证明，因为输出位相关。这里同一内核的实际对照才支持“G2变换后的分布使当前固定外层 BP 更难译”的判断。正确先验将失败100次降到80次，但尚不足以恢复原始组的性能。

## 结论与边界

本次没有发现 C++/Python 输出不一致；在固定 C++ 内核后，性能下降仍然存在。因此不能把这次下降归因于换用 Python 实现。也不能据此断定 G2 构造非法、最优译码必然失败，或所有级联方法都差。

剩余问题是当前变换后信道、外层矩阵与有限轮数 BP 的配合。后续可在同输入上比较增加迭代预算及实际 X 估计生成的条件符号先验，分别判断收敛预算和可用相关信息的作用。真值只用于离线错误计数，不能用于在线选择候选或生成条件先验。

## 实现与复现

- `run_bp_implementation_audit.py`：输入生成、两份 BP 核对、统计。
- `audit_bp_bridge.cpp`：向既有 C++ BP 传显式符号先验，不接收错误真值。
- `NB_BP_Decoder::decode_component_prior`：显式先验入口，原入口仍构造原先验后调用同一内核。
- 结果包括输入、C++输出、离线真值、逐例JSON及源文件哈希。

在仓库根目录执行：

```bash
cmake -S . -B /tmp/git-demo-bp-audit-build
cmake --build /tmp/git-demo-bp-audit-build --target audit_bp_bridge -j4
python3 experiments/gf256_cascade/run_bp_implementation_audit.py \
  --bridge /tmp/git-demo-bp-audit-build/audit_bp_bridge \
  --frames 100 --cross-frames 20 --max-iters 100 \
  --fm 0.0475 --seed 20261121 \
  --output experiments/gf256_cascade/results/bp_implementation_audit_repeat
```

保存的运行用时约135秒，不含编译；机器变化会影响耗时。
